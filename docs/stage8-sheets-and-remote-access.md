# Stage 8 —— Excel 各 Sheet 软件化展现 + 手机/外网访问

> 完成时间：2026-09-26
> 目标：① 各 Sheet 的数据进入软件后，用**软件的方式**展示与检索，不再照搬 Excel 网格；
> ② 手机、其他电脑（含外网）都能打开这套系统。

---

## 一、为什么改

前一版 `/sheets/[sheet]` 是「Excel 原样镜像」：列名、列序、无表头列、整列空列全部照搬，
真实效果就是把 Excel 塞进浏览器 —— 横向滚动很长、搜索只能整行模糊匹配、手机上完全没法看。
本次改造保留「数据与 Excel 一致」这一点，把**展现层**换成标准业务系统的数据表。

数据层面没有做任何迁移或改写：仍然读 `SheetRow` 表（导入时逐格抓取的原值，
公式取缓存结果、日期格式化为 `YYYY-MM-DD`），历史脏值（`×`、错位列、身份证/电话错位）一律保持原样。

## 三、关键设计决策

### 1. 表头处理（只影响显示，不动数据）
- 空表头 → 用 Excel 列字母命名（「第 F 列」）；
- 重名表头 → 加序号区分（`联系人电话` / `联系人电话（2）`）；
- 已知缺失：**「在职」Sheet 第 5 列整列是姓名，但 Excel 表头为空** → `HEADER_FIXES` 补为「姓名」。

### 2. 敏感列服务端打码（重要）
身份证 / 银行卡 / 电话 / 地址 / 薪资列默认打码（`420683********2815`）。
最初实现放在客户端，验收时发现**原始值仍随页面数据下发到浏览器**（页面源码里能搜到完整身份证号）——
等于没打码。现已改为**服务端打码后再下发**：未勾选「显示完整信息」时，
浏览器根本拿不到完整值；勾选后（`?reveal=1`）服务端重新查询并下发完整值。

### 3. 检索在服务端、偏好在前端
- 关键词 / 按列筛选 / 排序 / 分页 → 写在 URL 上（可刷新保持、可分享链接）；
- 列的显示隐藏、是否折叠整列空列 → `localStorage`，纯展示偏好，不占 URL。

### 4. 全空列默认折叠
例如「数据库」46 列里大部分列整列为空。默认隐藏整列为空的列，
右上角「列（n/m）」面板里可勾选「显示空白列」展开，面板同时显示每列的有值行数。

### 5. 远程访问的 Cookie 坑（关键修复）
`sessionCookieOptions()` 原先在 production 下强制 `secure: true`。
浏览器**只在 HTTPS（或 `http://localhost`）下保存 Secure Cookie**，
所以用 `http://192.168.x.x:3000` 访问时会出现「登录返回成功，刷新又回登录页」。
现改为按请求真实协议判断（兼容 `x-forwarded-proto`），隧道（https）自动带 Secure，
局域网 http 不带 —— 两种入口都能正常登录。

### 6. 外网访问做法
用 Cloudflare Quick Tunnel（`cloudflared`）：无需注册、无需域名、自动 https，
关掉窗口即下线。首次运行自动下载程序；下载路径按实测顺序重试
（直连 → 各代理 → GitHub 镜像 → fetch 兜底），低速度链路会被 curl 自动掐掉换下一条。
隧道建立时先试直连，不通则带 `HTTPS_PROXY` 并强制 `--protocol http2` 重试。

## 五、怎么用

```bash
# 启动（会直接打印本机 / 局域网访问地址）
npm run serve

# 首次：放行 Windows 防火墙 3000 端口（管理员 PowerShell）
npm run firewall

# 手机在外面用 4G 访问：另开一个窗口
npm run tunnel
```

| 场景 | 地址 |
| --- | --- |
| 本机 | `http://localhost:3000` |
| 局域网（同一 WiFi） | `http://192.168.31.174:3000` |
| 外网（4G） | `npm run tunnel` 输出的 `https://xxxx.trycloudflare.com` |

软件内「基础设置 → 访问入口」页会实时列出可用地址、复制按钮和排错顺序。

## 六、已知限制

1. 隧道是**临时地址**，窗口关掉即失效、下次启动换新地址。要固定网址需改用 Tailscale
   或 Cloudflare 命名隧道（需域名 / 账号）。
2. 局域网访问是 **http 明文**，仅建议在可信网络内使用；外网隧道为 https。
3. 隧道开启期间，任何拿到网址的人都能看到登录页 —— 系统本身有登录校验，
   请使用强密码并及时关闭隧道窗口。
4. Sheet 页面是**只读镜像**，不提供在此处编辑；增删改员工仍在「数据管理 → 员工档案」。
5. 检索与排序在服务端内存中完成（单表最大约 2000 行），当前数据量下响应 < 200ms；
   若单表增长到数万行需要改为数据库层检索。
