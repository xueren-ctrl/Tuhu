### 1.1 关键结论：`数据库` 是唯一数据源

读取派生 Sheet 的公式可以证实这一点。例如 `在职!B3`：

```
=IF(XLOOKUP(1,(数据库!$E:$E=$E3)*(数据库!$C:$C=$C3),数据库!B:B,"没找到",0)="","",
   XLOOKUP(1,(数据库!$E:$E=$E3)*(数据库!$C:$C=$C3),数据库!B:B,"没找到",0))
```

即：`在职` / `离职` / `南昌3店` / `运营部` / `运营部离职` 等 Sheet 都是
**以「姓名 + 入职时间」为联合键，去 `数据库` Sheet 里 XLOOKUP 取数**。

- 因此**只有 `数据库` Sheet 含真实数据**，其余都是视图。
- 这也意味着 `数据库` 中「姓名 + 入职时间」是业务上的自然键，重名或同一天入职会导致取数歧义
  （实测 `数据库` 中有 **8 组** `姓名+入职时间` 完全重复）。
- 迁移到软件后，系统改用 `employee_id` 作为唯一键，彻底消除该隐患。

### 4.3 在职 / 离职状态的判定依据

`数据库` Sheet **没有独立的在职/离职状态列**。实测各信号覆盖情况：

| 信号 | 命中（按姓名+入职日期去重后） |
| --- | --- |
| 「离职」Sheet 名册 | 1400 条 | 
| 「在职」Sheet 名册 | 293 条 |
| `AA` 列可解析为日期 | 1129 条 |
| `Z` 列离职原因非空 | 516 条 |
| `AA` 列文本含离职语义 | 80 条（其中部分为「重新入职」，需排除） |

**实测交叉情况：**

- 「在职」与「离职」名册**同时出现同一人**：10 条（已脱敏，共 10 条，详见导入报告的 STATUS_CONFLICT 异常）
- 在「在职」名册但 `数据库` 中带离职日期：5 条 → 判定为**离职**并标记 `STATUS_CONFLICT`
- 在「离职」名册但 `数据库` 中无任何离职信息：162 条 → 判定为**离职**、离职日期留空，标记 `RESIGN_DATE_MISSING`
- `数据库` 中既不在「在职」也不在「离职」名册：约 290 行 → 完全依据 `Z`/`AA` 列判定

**采用的判定规则（任一命中即为离职）：**

1. 出现在「离职」名册；或
2. `AA` 列可解析出日期；或
3. `Z` 列离职原因非空；或
4. `AA` 列文本含「离职/辞职/自离/已离/被辞/劝退/开除」**且**不含「重新入职/又入职/回归/再入职」

否则为**在职（ACTIVE）**。

> ⚠️ **绝不会因为某个字段为空就把所有人判成在职**，也绝不会因为名册缺失就漏判离职。
> 冲突与缺失全部写入异常报告，等待人工复核。

### 4.4 其他数据问题

| --- | --- | --- |

## 6. 迁移映射总览

`数据库` Sheet 46 列 → 数据库 `Employee` 表 **53 个业务字段 + 8 个系统字段**：

| Excel 列数 | 数据库业务字段数 | 说明 |

| --- | --- |

### 6.1 补充：溯源表 `EmployeeSourceRow`

除 `Employee.sourceRowNo`（记录首次来源行）之外，另建 **`EmployeeSourceRow`** 表持久化
「**每一条 Excel 数据行 → 员工记录**」的完整映射，`(sheet, rowNo)` 唯一。

原因：Excel 中同一名员工可能出现在多行（重复登记、同一段任职被录入两次），
这些行会合并到同一条 `Employee` 上。若行号只存单值，后一行会覆盖前一行，
下次重复导入时前一行就找不到归属 → 会产生重复员工。
有了这张表，导入脚本可以**无限次重复执行而不产生任何重复员工**。

### 6.2 合并单元格陷阱（必须注意）

「数据库」Sheet 表尾有 4 个说明性合并行：

| 合并区域 | 内容 |
| --- | --- |
| `A1930:M1930` | 南昌3店 |
| `A1949:K1949` | 运营部 |
| `A1960:K1960` | 运营部离职 |
| `A1971:K1971` | 其他 |

ExcelJS 会把主格的值**回传给区域内每一个从属格**，且 `isMerged` 对区域内每个格子都为 `true`。
若不排除从属格（判定方式：`cell.master.address !== cell.address`），
`E1930` 等格会被当成有值 → **凭空产生 4 名幽灵员工**，并污染门店/职位主数据。
导入脚本已在 `readCellText()` 中统一排除。

### 6.3 纯日期字段的存储口径

所有「纯日期」字段（入职日期、离职日期、面试日期）统一以 **UTC 零点**入库。
这样 `toISOString().slice(0,10)` 与任何时区的本地日期都一致，不会出现跨时区串日
（例如 `2021-03-22` 不会在 UTC+8 下变成 `2021-03-21`）。
时间戳（`createdAt` / `updatedAt`）仍按本地时区显示。

## 8. 结论

1. `数据库` Sheet 是**唯一真实数据源**，其余 Sheet 均为 XLOOKUP 派生视图 → 迁移它即完成核心数据迁移。
2. 数据区 **1994 行**，其中**有效业务行 1934 行**，全部纳入迁移；60 行为空行，跳过并记录。
3. **46 列全部保留**，不做字段删减；同名重复列改用唯一内部名并标注「重复列」与 Excel 列位置。
4. 长期存在的**列错位问题**（身份证/银行卡/电话互串）采用「内容识别 + 安全归位 + 全量记录」处理，
   只在目标字段为空时归位，绝不覆盖，绝不修改原 Excel。
5. **状态判定**综合 4 类信号，冲突与缺失全部上报，不作为静默处理。
6. 长数字字段全程字符串处理，避免精度丢失与前导零丢失。
7. 所有异常均有明细（员工姓名 + 原始行号 + 异常字段 + 原因），落库 `ImportIssue` 表并输出到
   `docs/import-report.md`。
