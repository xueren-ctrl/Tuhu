## 三、头号 Bug：脱敏值被写回数据库（要求 1）

### 现象
确认导入时，员工手机号在数据库里从 `13800138000` 变成了 `138****8000`（脱敏串），身份证号、银行卡号等敏感字段同理被不可逆地写坏；修复后写库使用 `rawNewValue` 真实值，列表接口才重新脱敏展示。

### 根因
旧版 `commitPreview()` 直接读取 Diff 里的 `newValue` 写库，而 `newValue` 在生成时已经过 `maskByField()` 脱敏。展示层和写库层共用了同一个值，**写库层拿到的本应是真实值，却拿到了脱敏值**。

### 修复
在 `lib/excel-import/diff.ts` 中，每条 `FieldChange` 同时产出两套值：

- `displayOldValue` / `displayNewValue`：**脱敏后**，仅用于页面展示；
- `rawOldValue` / `rawNewValue`：**真实值**，仅用于写库。

落库的 `diffJson` 与接口返回**只含 display 值**，服务端永不保存或外发原始敏感值。提交时 `commitPreview()` **重新解析同一份上传文件**，用 `raw` 值写库（`toWriteValue()` 强制要求存在 `rawNewValue`，缺失即中止并报错，绝不静默落库）。

### 验证（stage5-test.mjs）
- `S5-02`：预览 Diff 的 display 值为掩码（`139****9000`），与 `maskByField()` 一致；
- `S5-03`：预览返回的 JSON 中**不含**明文手机号（`13900139000`），证明 raw 不外发；
- `S5-04`：确认写入后，数据库 `phone` 字段为明文 `13900139000`（真实值），而非掩码。

## 四、共享解析底座（要求 2、3）

新建 `lib/excel-import/`，作为全项目唯一的 Excel 解析实现：

| 文件 | 职责 |
| --- | --- |
| `types.ts` | `EmployeeRecord` / `EmployeeStatus` / `ParseIssue`，值覆盖 46 列 |

| `normalization.ts` | 日期/数字/身份证/银行卡/合并单元格从属格判定 |
| `status.ts` | 在离职状态综合判定（含离职名册交叉比对） |
| `issue.ts` | 解析期异常收集（不静默） |
| `parser.ts` | `parseWorkbook` —— 表头校验、合并单元格防护、内容识别归位 |

| `index.ts` | 统一出口 |

`scripts/import-excel.ts` 与 `lib/import-preview-service.ts` 现在都从 `lib/excel-import` 取能力，删除旧的 `lib/import-parser.ts`，**预览与正式导入不再可能口径漂移**（曾经因两套实现漏掉离职名册交叉比对，差点把 171 名离职员工改回在职）。

## 五、事务状态机（要求 4、5）

```text
PENDING → COMMITTING → SUCCESS | PARTIAL | FAILED
                         ↑失败可重试           DISCARDED（终态）
```

- 逐员工写入，部分失败**绝不**把批次标为 `COMMITTED`；
- 记录成功/失败条数与失败员工明细，允许「只重试失败项」（`retry=1`）；
- 创建预览瞬间冻结数据库版本指纹（员工/门店/职位/部门/别名任一被改都会变），提交前复核，不一致直接拒绝并要求重新预览，杜绝「页面看到 A、实际写入 B」。

## 六、结果口径（要求 7）

导入预览与正式导入统一使用六类结果：

- **新增**：匹配不到任何去重键，作为新员工插入；
- **修改**：匹配到已有员工且存在字段变化；
- **未变化**：匹配到已有员工且所有字段完全一致，跳过写入（幂等重跑不再产生无意义写库）；
- **跳过**：整行/姓名行为空；
- **异常**：解析期异常（列错位、身份证异常、日期无法解析等），全部进 `ImportIssue` 与 `import-report.md`，不静默；
- **失败**：数据库写入报错。

> 注：`scripts/import-excel.ts` 新增 `unchanged` 计数（一次性加载全量快照做内存比对，不增加逐行查询），幂等重跑时绝大多数行计入「未变化」而非「更新」。

## 七、重复员工重定义（要求 8）

数据质量中心把「重复」拆为两种语义不同的类别，不再混显：

- `exact-duplicate`：**姓名 + 身份证号 + 入职日期** 完全相同 —— 系统已判定为同一段任职被录入多次，需人工核对后停用多余记录；
- `no-identity-key`：身份证号 / 手机号 / 入职日期**全为空**，系统**无法判定**是否重复 —— 这只是「待补录」，不是「已判定重复」。

二者在 `lib/data-quality-service.ts` 的归类逻辑、统计口径、明细查询上完全分开；`listExactDuplicateIds()` 可精确列出真重复记录主键。
