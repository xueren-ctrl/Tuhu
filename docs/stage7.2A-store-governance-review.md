## 3. 当前候选算法规则（未做任何修改）

本阶段的候选由生产代码中既有的两个函数实时计算得出，**Stage 7.2A 未修改任何算法逻辑**：

- `findAliasCandidates()`（`lib/store-service.ts`）：对**全部 ACTIVE 门店**两两比对，命中任一条即成候选对：
  1. 两名称**去掉尾部「店」字后完全相同**；
  2. 或**一方为另一方名称的前缀**，且**名称长度差 ≤ 3**。
- `findMergeClusters()`（`lib/store-merge-service.ts`）：在候选对之上用并查集分组，
  得到候选簇（≥2 家成簇）；每簇的「建议主门店」= 在职人数较多者（相同则总人数较多，
  再相同则取 id 较小者）。

> ⚠️ **以上规则只表示「名称疑似相关」，不能作为「同一家门店」的最终业务判定。**
> 名称相似可能来自历史写法差异，也可能确实是不同门店，必须由人工结合业务事实判断。
